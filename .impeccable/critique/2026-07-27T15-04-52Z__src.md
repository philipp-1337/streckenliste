## Design-specificity verdict

The product truth is highly specific: Jagdjahr, Abschuss terminology, species-derived fields, Jäger assignments, status review, official print and district context make this unmistakably Streckenliste. The forest-and-paper visual language is coherent. Interaction design is less specific and less consistent: generic white CRUD cards, equal-weight icon actions, several modal grammars, and a long all-at-once capture form leave some surfaces feeling like a conventional administration dashboard.

The deterministic scan found 21 advisory font-size findings. Fifteen are verified non-print drift below the documented 12–14px secondary floor; six in `PrintContent.tsx` are intentional print-density exceptions. Browser inspection was unavailable (`No browser is available`), so visual conclusions are source-backed rather than screenshot-backed.

## What works

- Hunting-domain logic is translated into the interface unusually well, including dependent categories, automatically derived terminology, hunting-year context, permissions, history and print output.
- Responsive design is substantive: mobile cards, configurable table density, safe-area navigation, persistent preferences and 16px form text.
- Operational feedback is generally thoughtful through skeletons, counts, badges, disabled/loading labels, validation, previews and capability-specific push explanations.

## Priority issues

### P0 — Standardize dialogs and confirmations

`ConfirmDialog.tsx` provides the correct accessible baseline, but `ImportDialog.tsx`, `KategorienFixDialog.tsx`, `AblehnungsModal.tsx`, `HistoryModal.tsx`, `PdfDownloadDialog.tsx`, and toast-based delete/logout confirmations use different semantics and lifecycle behavior. Several lack labelled dialog semantics, focus trapping/restoration and Escape handling; destructive toast confirmations expire.

Fix: extract one focus-managed dialog shell and compose every modal and non-expiring confirmation on it. Preserve busy-state close protection.

Suggested command: `$impeccable harden dialogs`

### P1 — Make record capture the unmistakable primary action

`ActionButtons.tsx` presents new entry, filter, legend and PDF with equal icon-only weight. `EintragForm.tsx` exposes roughly 9–11 decisions at once.

Fix: use a labelled primary “Eintrag erfassen” action, demote utilities, group the form into required capture, derived result and progressively disclosed additional information, and leave a durable in-context success summary.

Suggested commands: `$impeccable distill overview`, `$impeccable layout EintragForm`, `$impeccable clarify EintragForm`

### P1 — Make mobile records safe by default

`App.tsx` defaults mobile records to table view despite the design system’s card-first promise. Card and table actions use different affordances, with swipe actions carrying discoverability risk.

Fix: default first-time mobile users to cards, preserve stored expert preference, use a visible actions trigger, and align action names/order across representations.

Suggested commands: `$impeccable adapt EintragTable`, `$impeccable harden EintragTable`

### P1 — Build recoverable empty, error and loading states

Filtered-zero, first-use empty and load failure are not consistently distinguished. Some failures are transient toasts; History can remain loading after rejection; stats can show an empty analytical shell; import errors lack row-level remediation.

Fix: provide state-specific explanations and CTAs, inline retry paths, meaningful route skeletons, a no-data statistics state, and row-numbered import diagnostics plus a template.

Suggested commands: `$impeccable onboard empty-states`, `$impeccable harden system-states`, `$impeccable clarify errors`

### P1 — Close systemic accessibility gaps

`Nav.tsx` removes focus outline without a replacement. Repeated controls are below the documented 44px floor, including quantity, table-card actions, Jagdjahr and modal controls. Motion-reduction support is inconsistent. Charts largely communicate through color and pointer tooltips.

Fix: standard focus-visible treatment, ≥44px targets, reduced-motion variants, `aria-current` navigation state, persistent mobile fullscreen exit and a textual/table alternative for statistics.

Suggested commands: `$impeccable harden navigation`, `$impeccable adapt controls`, `$impeccable animate motion-policy`

### P2 — Clarify navigation and analytics hierarchy

Logout is presented as a peer destination, Stats lacks the shared route heading, and mobile chart controls are hidden. The statistics surface reports comprehensively without clearly stating the operational takeaway.

Fix: separate “Abmelden” from destinations, apply shared page hierarchy, keep fullscreen exit accessible at every breakpoint, and add a concise season summary.

Suggested commands: `$impeccable clarify navigation`, `$impeccable adapt StatistikPanel`

### P2 — Enforce the documented type and theme system

Fifteen verified non-print locations use 10–11px text. Semantic colors and radii remain repeated Tailwind literals rather than enforced product tokens.

Fix: raise meaningful metadata to at least 12px, preferably 14px; document any intentional compact badge/chart size; map design colors and surfaces to semantic utilities. Keep the print ramp as an explicit exception.

Suggested commands: `$impeccable typeset src`, `$impeccable document`

## Cognitive load and emotional journey

The calm login and strong district/year context establish trust. Auto-derived hunting terminology creates the intended confidence peak. The main valley is capture and review: the long form, equal-weight icon toolbar, dense records and inconsistent modal rules make routine work feel more administrative than field-ready. Statistics provide satisfying season visibility, but density and visual-only chart semantics limit comprehension. Success and failure too often disappear into transient toasts rather than leaving durable reassurance.

## Persona red flags

- A hunter capturing outdoors on a phone encounters small controls, a long form, default table view and subtle icon actions.
- An older or infrequent member must learn icon meanings, swipe actions, tri-state sorting and column configuration.
- An admin reviewing many records faces dense actions and inconsistent confirmation behavior, increasing fatigue and error risk.
- Keyboard, screen-reader and color-vision users encounter missing modal semantics, invisible nav focus and chart information that depends on color or pointer tooltips.
- A user on poor connectivity receives skeletons initially but not always durable inline recovery after failure.

## Minor observations

- Standardize “Anmelden/Abmelden,” “E-Mail,” and correct “Keine Account” to “Kein Account.”
- Add `aria-current` to the active navigation destination.
- Use a neutral reset-password response that does not reveal whether an account exists.
- Explain import format and status workflow contextually.
- Treat `PrintContent.tsx`’s dense type as a documented print-only exception.

## Questions

- Is the primary promise complete ledger maintenance or rapid field capture? The current UI prioritizes the former.
- Which advanced entry fields must exist at capture time, and which belong to later review?
- What decision should the statistics page help a district make?
